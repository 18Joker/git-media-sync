# 清单同步（生成 + 精准下载）设计文档

## 意图与背景

现有「列出文件」递归扫描云盘整个项目目录：阿里云盘自动同步会把所有文件夹（含大量空文件夹）传上云端，每个文件夹一次 API 调用且 aligo 限速 1 次/秒，导致扫描极慢。

改为**清单驱动**：自媒体项目维护一份特殊后缀的清单文件（JSON 内容），随自动同步上传到云盘项目根目录；工具先读清单，再按清单精准定位云端文件，跳过全盘扫描。同时在本工具内提供**清单生成**功能：扫描本地项目，按后缀白名单收集 git 未跟踪的素材文件，写出清单，形成「设备 A 生成 → 云盘同步 → 设备 B 精准下载」闭环。

## 目标

- 工具内一键为已配置项目的本地路径生成 `media.gmsync`（纯本地操作，无需登录云盘）。
- 后缀白名单：内置默认清单 + 项目级覆盖。
- 「列出文件」优先读云盘清单精准定位；清单缺失时回退现有全量扫描。
- 下载链路（git 过滤、大小比对、三态勾选、原子覆盖、取消、进度、缓存）完全不变。

## 非目标（不做）

- 不做上传、不删除本地文件（沿用原定位）。
- 不做哈希校验（沿用按大小比对）；清单不含 file_id（云端内部 ID，由工具解析时现查）。
- 不用云端搜索 API；不做清单的版本管理/合并。
- 清单生成方即本工具，不再另写独立脚本。

## 约束

- 阿里云盘自动同步**按后缀过滤**：清单后缀必须独特，不能用 `.json` 等常见后缀，否则会把项目中 git 已管理的同后缀文件也同步上云。
- aligo `request_interval=1`：精准定位的 API 次数必须与素材所在目录数挂钩，与空文件夹数无关。
- 清单来自云端（不可信输入）：`path` 必须校验，防止写到本地项目之外。
- 老 `config.json` 无新字段时自动走默认，不迁移。

## 方案选型

精准定位方式：

- **A. 逐文件 `get_file_by_path`**：每个文件按路径段逐级查询，文件多时调用仍多。放弃。
- **B. 按父目录分组 + 单层列目录（选定）**：清单按所在目录分组，每个目录解析一次路径、列一次文件，挑出清单内文件。API 次数 ≈ 素材实际所在目录数，与空文件夹无关，复用现有列目录代码。
- **C. 云端 `search_files`**：依赖搜索索引，新同步文件可能搜不到、同名误匹配。放弃。

## 关键决定

### 清单文件约定

- 固定文件名 **`media.gmsync`**；生成时写在 `{local_path}/media.gmsync`，下载时读 `{cloud_path}/media.gmsync`。
- 后缀 `.gmsync`（git-media-sync 缩写）：用户把它加进自动同步后缀白名单即可，不波及常见格式。
- 内容为 UTF-8 JSON：

```json
{
  "version": 1,
  "generated_at": "2026-11-12T21:30:00",
  "files": [
    { "path": "assets/cover.png", "size": 102400 }
  ]
}
```

- `path`：相对项目根目录，正斜杠，无前导斜杠；`size`：字节数。
- `version` 目前固定 1；`generated_at` 为本地生成时间（ISO 格式），日志展示用。

### 生成（本地）

- 入口：按钮栏「列出文件」旁加「生成清单」，作用于当前选中项目的本地路径；未登录云盘可用。
- 流程：`git_tracked()` 取跟踪列表（非 git 仓库报错停止）→ `os.walk` 递归扫描，跳过 `.git` 与 git 已跟踪文件 → 后缀白名单过滤（大小写不敏感）→ 组装 JSON → tmp + `os.replace` 原子写入，重复生成直接覆盖。
- 被 .gitignore 忽略的文件照常纳入（素材通常即被 ignore 的未跟踪文件）。
- 后缀配置：`Project` 增加 `exts: str = ""`（逗号分隔，如 `jpg,png,mp4`），留空用内置默认；项目编辑弹窗加「素材后缀」输入行。
- 内置默认：`jpg jpeg png gif webp bmp svg mp4 mov mkv avi webm m4v mp3 wav flac m4a psd`。
- 完成日志：`已生成 media.gmsync：N 个文件，共 X MB`。

### 精准下载（云端）

- `_list_worker` 先尝试读清单：`get_file_by_path` 定位 → 取下载链接读内容（小文件，2 次 API）。
- 清单存在 → 解析校验 → 按父目录分组 → 每组 `get_folder_by_path` + 单层 `get_file_list`，按名匹配得到 `CloudFile(file_id, size)`。
- 边界：
  - 清单缺失 → 回退现有全量扫描（日志说明）。
  - 清单 JSON 损坏 / `version` 不支持 / `path` 含 `..`、绝对路径、非法字符 → 明确报错，不静默回退。
  - 清单内文件云端不存在，或云端大小与清单不符（同步未完成）→ 跳过 + 日志警告，不中断。
- 清单文件本身不进入下载列表；解析结果走现有 `build_entries` → 树 → 下载，缓存沿用 `cache.json`。
